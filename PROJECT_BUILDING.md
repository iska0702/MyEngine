# Сборка .idkp самим движком

В Windows-редактор встроен сборщик проектов. Обычная сборка больше не запускает PowerShell, build.bat, Visual Studio или компилятор C++: она использует подготовленный игровой runtime, проверяет его файлы и упаковывает данные проекта.

## В редакторе

1. Откройте проект `.idkp`.
2. Выберите **Project → Build game...**. То же окно доступно из Project Settings.
3. Оставьте текущий проект или выберите другой `.idkp` через Browse.
4. Выберите Standalone, Steam или Epic Online Services и нажмите **Build game**.

Перед сборкой текущего открытого проекта редактор сохраняет сцену. При ошибке сохранения сборка не начинается. Другой выбранный проект собирается из уже сохранённых файлов. Работа идёт в фоновом потоке: доступны этапы, прогресс, журнал и Cancel build. После успеха можно открыть Build или запустить игру.

Результат появляется рядом с выбранным `.idkp`:

```text
Project/
  Game.idkp
  Build/
    Idontknow.exe
    Contents/
      content01.pak ... content10.pak
    ThirdParty/
      ...нужные библиотеки выбранного runtime...
```

Имена проекта, стартовая сцена/уровень, меню, заставка, физические настройки и ASD ID берутся из `.idkp`. Поддерживаются собственная папка Content и пути с пробелами/кириллицей. Ресурсы, настройки и исходная сцена упаковываются в AES-256-GCM; текстуры проходят подготовку mip-уровней и GDeflate, затем шифруются. Включены манифест целостности DLL и проверка результата.

Журналы находятся в **Saved/BuildLogs** проекта. Предыдущий удачный Build сохраняется в **Saved/BuildHistory**; ошибка и отмена не заменяют его. При наличии посторонних файлов в Build сборщик отказывается его заменять. Запущенную игру следует закрыть перед публикацией новой сборки. Файлы проекта, исходные ресурсы и сцена не перезаписываются упаковщиком.

## Командная строка

```powershell
./EditorBuild/Idontknow.exe --build-project "D:/MyEngine/Projects/Test/Test.idkp"
./EditorBuild/Idontknow.exe --build-project "D:/Projects/Game/Game.idkp" --build-platform standalone
```

`--build-platform` необязателен: по умолчанию используется значение из проекта. Команда не создаёт D3D12-редактор; успешный процесс возвращает 0, ошибка — 2. После регистрации расширения редактором также доступен пункт **Build project** в контекстном меню `.idkp` Проводника.

`tools/Build/BuildProject.ps1` по умолчанию обращается к этому же встроенному сборщику. Старый путь с компиляцией движка оставлен для разработчика SDK через `-CompileEngine`.

## Готовые runtime в SDK движка

Редактору нужны предсобранный игровой EXE, его библиотеки, библиотека шейдеров и маленький нативный инструмент подготовки текстур. Они хранятся внутри **EditorBuild/ThirdParty/Idontknow/BuildSupport/Windows/<platform>**. Это часть распространяемого редактора, а не папка проекта и не требование установить Visual Studio пользователю.

Каждый runtime имеет аутентифицированное описание и SHA-256 файлов. Повреждённый, неподходящий по ключу или отсутствующий runtime не используется. Ключ шифрования и формат runtime должны соответствовать редактору. Изменения C++-движка требуют обновить runtime SDK; изменения ресурсов, Lua и настроек проекта требуют только обычной упаковки.

Подготовка SDK разработчиком движка выполняется один раз после сборки редактора:

```powershell
./build.bat editor standalone
./tools/Build/BuildRuntimeSupport.ps1
```

Этот служебный шаг использует установленный компилятор и SDK Steam/EOS для соответствующих вариантов. Обычный пользователь получает готовую папку EditorBuild и выполняет сборку проекта кнопкой. Для подготовки одного варианта есть `-Platforms standalone`, `steam` или `epic`. Существующий совместимый standalone Build можно передать через `-StandaloneBuild`.

## Проверки

`tools/Diagnostics/CheckProjectBuilder.ps1` проверяет отдельные тестовые проекты в Diagnostics: пробелы и Unicode, нестандартные пути, шифрование, подготовку текстур, сохранность исходников, отмену, подмену runtime, выход пути за границы проекта, отсутствие платформы и защиту предыдущего Build.
